# premium-ai-manager

## Selectel / VDS: запуск без домена

1. На Railway отключите GitHub Autodeploys в Source и удалите активный deployment через Remove.
   Переменные сохраните у себя; весь проект и чужие сервисы не удаляйте.
2. На сервере обновите код и соберите образ:

```bash
cd /opt/premium-ai-manager
git pull --ff-only
docker build -t premium-ai-manager .
python3 setup_env.py
```

Настройщик запрашивает токен Telegram и ключ Яндекса скрытым вводом.
Для Яндекса также нужен URI выбранной модели, например `gpt://FOLDER_ID/yandexgpt/latest`.
`FOLDER_ID` замените ID каталога Yandex Cloud. Enter вместо ключа оставляет сценарный режим.
Секреты сохраняются в `/etc/premium-ai-manager.env` с правами 600, вне Git и Docker-образа.
Если меняете настройки повторно, введите оба секрета заново; после этого пересоздайте контейнер.

```bash
docker run -d --name premium-ai-manager --restart unless-stopped \
  --env-file /etc/premium-ai-manager.env \
  --mount type=volume,source=premium-ai-manager-data,target=/data \
  --log-opt max-size=10m --log-opt max-file=3 \
  premium-ai-manager python -u poll.py
docker logs --tail 30 premium-ai-manager
```

При повторном запуске сначала `docker stop premium-ai-manager`, затем `docker rm premium-ai-manager`.
Не запускайте одновременно Railway и polling или две копии polling с одним токеном.
Polling автоматически проверяет токен через getMe и удаляет webhook без удаления ожидающих обновлений.
Строка `Polling started` подтверждает запуск Telegram; работоспособность Yandex API проверяется первым диалогом.
Порты на сервере публиковать не нужно. HTTP `/health` в polling-режиме не запускается.
Для webhook-интеграции amoCRM позже потребуется отдельный публичный обработчик.

Позиция очереди Telegram сохраняется в Docker volume. История диалога всё ещё в RAM.
Демо обрабатывает очередь последовательно: долгий ответ задерживает следующие чаты.
При постоянной ошибке отправки обработка повторяется; проверяйте логи.
Дедупликация не обеспечивает exactly-once при падении между отправкой и сохранением позиции.
До работы с реальными лидами нужны постоянное хранение диалогов и надёжная очередь.

Безопасный тестовый контур автономного AI-менеджера для Telegram Business.

## Сейчас готово

- webhook Telegram Business;
- ответы от имени подключённого бизнес-аккаунта;
- обязательный секрет webhook;
- allowlist тестовых Telegram chat ID;
- отсутствие токенов и персональных данных в репозитории;
- `/health` для проверки сервера.

ИИ и amoCRM подключаются после согласования провайдеров и проверки каналов клиента.

## Запуск

```bash
pip install -r requirements.txt
# Export variables from .env.example in your shell before starting.
uvicorn app:app --reload
```

Секреты задаются только в переменных окружения сервера.

## Railway

Задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET` (случайный секрет из латинских букв, цифр, `_` и `-`) и `ALLOWED_CHAT_IDS`.
Публичный домен берётся из `RAILWAY_PUBLIC_DOMAIN`; при необходимости укажите `PUBLIC_BASE_URL` с `https://`.
При запуске сервер регистрирует `/telegram/webhook` и проверяет регистрацию в Telegram.
Секрет передаётся в заголовке Telegram, а не в URL. `/health` показывает `webhook_ready`.

Пустой `ALLOWED_CHAT_IDS` запрещает все ответы. Для теста укажите ID собеседника,
или `*`, чтобы отвечать всем в чатах, разрешённых в настройках Telegram.
который пишет бизнес-аккаунту, а не ID владельца аккаунта.
В Telegram разрешите боту только выбранный тестовый чат.
Исходящие сообщения владельца и ботов игнорируются.

## Демо флориста

Вымышленное ателье «Тихий сад», адрес и каталог находятся в `florist.py`.
Без API работает сценарный показ: бюджет → варианты → выбор → доставка/самовывоз → учебное резюме.
Пример: «Букет маме до 7 тысяч, без роз», затем «второй», затем «самовывоз».
«Заново» очищает подбор. Фото и голосовые пока не распознаются, фотографии товаров не загружены.
Первое сообщение явно сообщает о демонстрации. Реальные заказы, оплата и передача сотруднику не выполняются.

Для свободного ИИ-диалога задайте в Railway `YANDEX_API_KEY` и `YANDEX_MODEL_URI`
(URI выбранной модели из Yandex AI Studio). Ключ не коммитьте и не пересылайте в чат.
API ключу нужны соответствующие права на генерацию текста. `/health` показывает
`dialogue_mode: scripted` или `yandex`; значение `yandex` означает наличие настроек,
а не успешную проверку ключа. Первый настоящий диалог проверяет доступ к API.
Используется https://llm.api.cloud.yandex.net/foundationModels/v1/completion .
В модель передаётся текст последних 16 сообщений; Telegram ID не включается в запрос.
Сценарные ответы проверены тестами; ответы реальной модели требуют отдельной проверки после подключения ключа.

Память диалога и дедупликация последних 50 сообщений находятся в RAM одного процесса,
очищаются после часа бездействия (при следующем обращении) или перезапуска.
Это не сохранение лидов. Запускайте одну реплику/один worker.
Используйте вымышленные данные. Для реального запуска нужны постоянное хранение,
CRM, передача сотруднику и проверка качества модели на диалогах магазина.
